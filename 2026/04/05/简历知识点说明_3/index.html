一、文档加载与预处理 — 把“乱糟糟的原材料”变成“整齐的积木块”

RAG 的第一步是喂给系统各种文档（PDF、Word、网页）。但这些原始文档就像一堆 堆满杂物的房间：有格式混乱、广告、无关的表格、页眉页脚……你需要先 打扫、整理、切割，才能让后续的检索和生成用起来。

1. 核心任务（三步走）

步骤 作用 生活类比
加载 读取不同格式的文件（PDF、DOCX、HTML），提取出纯文本 从仓库里搬出各种箱子（PDF、Word），打开取出里面的东西
清洗 去掉噪声（HTML标签、特殊符号、空白行、页眉页脚） 把箱子里的杂物扔掉，只留有用的纸张
分块 把长文档切成适合模型处理的小段落（块），并保留少量重叠 把一本厚书拆成几页一沓的小册子，每两沓之间重复几行，避免切断关键信息

2. 常用工具与技巧

加载工具：Unstructured

  • 作用：支持 PDF、Word、PPT、HTML、电子邮件等 20+ 种格式，自动提取正文、表格、标题层级。
  • 简单使用：
  • 优点：自动识别段落、列表、表格，比手动用 PyPDF2 强太多。

清洗工具：BeautifulSoup + 正则

  • BeautifulSoup：专门对付 HTML/XML，可以 .get_text() 去掉标签，或者 find_all 保留特定标签内容。
  • 正则表达式：处理特殊模式，如删除 \n{3,}（多个换行）、\s+（多余空格）、去除邮箱/日期等不需要的信息。

分块策略 — 核心难点

分块方法 原理 适用场景 优点 缺点
固定长度分块 (RecursiveCharacterTextSplitter) 按字符数切，尽量在句号/换行处断开 通用，快速 简单 可能切断句子，丢失语义
语义分块 (SemanticChunker) 利用 Embedding 模型计算句子间的相似度，相似度低的地方切分 内容主题多变的长文档 保持语义完整性 慢，需要调用模型
递归分块 先按段落，段落太长再按句子，句子太长再按字符 层级结构明显的文档 适应性强 参数调优麻烦

重叠窗口 (overlap)：比如每块 500 字符，重叠 50 字符。作用：防止关键信息正好被切在边界上，导致检索时丢失。类比：两沓小册子之间重复几行，保证读者不会漏掉跨页的内容。

二、Embedding 与向量数据库 — 给文档块“贴坐标”，方便快速查找

经过上一步，我们得到很多文本块（Chunks）。但这些文本块是 非结构化 的，无法直接进行相似度计算。Embedding 把它们变成 浮点数向量（一串数字），向量数据库 负责存储和快速检索这些向量。

1. 核心概念

概念 作用 生活类比
Embedding 模型 将文本映射为高维向量（如 1024 维）。语义越相似的文本，向量在空间中的距离越近 给每个文本块标出经纬度坐标，意思相近的块坐标也相近
向量数据库 专门存储和检索向量的数据库，支持相似度搜索 一个超大体育馆，每个文本块是一个座位，按坐标排列；你可以快速找到离你最近的座位
余弦相似度 计算两个向量夹角的余弦值，值越大越相似（范围 -1~1） 看两个人面对的方向是否一致，方向越一致越相似
内积 向量点积，也用于相似度计算，但受向量长度影响 更看重“长度”和“方向”的综合效果

2. 常用 Embedding 模型（中文）

模型 维度 特点
BAAI/bge-large-zh 1024 智源开源，中文 SOTA，推荐
text-embedding-3-small (OpenAI) 1536 效果好，但需 API 调用
m3e-base 768 轻量，适合本地部署

3. 向量数据库 — FAISS（Meta 出品，本地最强）

FAISS 是 内存索引，不依赖外部服务，适合百万级以下的本地部署。

索引类型（你简历中提到的 HNSW / IVF）

索引类型 原理 查询速度 构建速度 内存占用 精度
Flat (暴力) 遍历所有向量计算距离 慢 O(N) 快 高 100%
IVF (Inverted File) 先聚类成几个中心，查询时只搜最近的几个簇 快 中等 中等 略降
HNSW (Hierarchical Navigable Small World) 构建多层图结构，类似跳表 极快 慢 高 很高

记忆：IVF 像图书馆按大类分区，你先去“计算机”区找，不用逛遍全馆。HNSW 像高德地图导航，有高速路和岔路，跳着走。

FAISS 实战（关键两步）

IndexIDMap 的作用

  • 默认 FAISS 返回的是向量在索引中的序号（0,1,2…），不方便映射回原始文档。
  • IndexIDMap 允许你给每个向量绑定一个外部 ID（如文档块编号、数据库主键）。
  • 检索时直接返回这个自定义 ID，方便你快速找到对应的文本内容。

4. Chroma — 轻量级向量数据库

  • 特点：纯 Python，嵌入式，无需单独部署；API 极简。
  • 适用：小规模实验（几千条文档）、快速原型。
  • 示例：

5. 余弦相似度 vs 内积

  • 余弦相似度：cosine = (A·B) / (|A||B|)，只关心方向，不关心长度。适合文本相似度（因为文本方向比长度更重要）。
  • 内积：dot = A·B，受长度影响。如果所有向量已归一化（长度=1），则内积等价于余弦相似度。
  • FAISS 默认：IndexFlatIP 用内积，IndexFlatL2 用欧氏距离（越小越相似）。实际使用中，常对向量做 L2 归一化，然后用内积等价于余弦。
