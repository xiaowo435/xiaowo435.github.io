一、LangChain & LangGraph — 大模型应用的“乐高流水线”

你可以把 LangChain 想象成一个 能把大模型、工具、记忆、提示词等零件自由拼装的“积木工厂”；而 LangGraph 则是给这个工厂加上了 “循环流水线”和“分拣机器人”，让 Agent 能来回跑、做决策。

1. LangChain 的核心组件（必须知道）

组件 作用 生活类比
Chain 把多个步骤（模型调用、工具调用、提示词模板）串起来 流水线上的工位，一个接一个干活
LCEL (LangChain Expression Language) 一种用 ` ` 管道符连接组件的语法
Memory 保存对话历史，让模型记住之前说了什么 给流水线配一个“记事本”，记录之前聊过啥
Callback 在 Chain 执行的不同阶段（开始、结束、出错）触发函数 流水线上装摄像头，记录每一步耗时、token数
Tool 让模型能调用外部函数（查天气、算数、搜数据库） 给机器人配一个工具箱，需要时就打开用

2. LangGraph — 给 Agent 加上“状态机”和“循环”

LangChain 的 Chain 是 有向无环图（只能往前走，不能回头），而 Agent 经常需要：思考 → 行动 → 观察 → 再思考（即 ReAct 模式），这需要循环。LangGraph 就是用来构建这种 带循环和条件分支 的状态图。

核心概念

概念 作用 类比
StateGraph 定义一个图，图里每个节点是一个函数（如调用模型、调用工具），节点间用边连接 地铁线路图，每个站点是一个节点，边表示能走到下一个站点
节点 (Node) 一个可执行函数，接收当前状态，返回更新后的状态 地铁站里的“处理中心”
边 (Edge) 从一个节点到另一个节点的转移 轨道
条件边 根据当前状态决定走哪条边 道岔，根据列车类型切换轨道

一个最简单的 ReAct Agent 图结构

  • Agent节点：模型输出 Thought + Action
  • 工具节点：执行 Action，得到 Observation
  • 条件边：如果 Action 需要继续，则回到 Agent 节点；否则结束。

你简历中提到的“解决死循环和重规划”

  • 死循环：Agent 反复调用同一个工具不前进 → 可以用 Critic 节点检查是否重复，达到上限就强制结束。
  • 重规划：发现 Observation 不够 → 返回 Planner 节点重新生成计划。

3. Tool 的定义（将任意 Python 函数包装成工具）

  • @tool 装饰器会把函数名、参数、文档字符串自动解析成模型可读的 JSON Schema。
  • 模型看到这个工具后，会输出类似：{"name": "get_weather", "arguments": {"city": "北京"}}。

4. 记忆口诀

Chain 串起流水线，LCEL 管道符相连，Memory 存对话历史，Callback 监控每阶段。
Agent 需要循环转，LangGraph 建状态图，节点边加条件，死循环重规划有出路。

二、LlamaIndex — 专为 RAG 打造的“智能图书馆”

如果说 LangChain 是通用积木，那 LlamaIndex 就是 专门为“检索增强生成”设计的瑞士军刀。它的核心任务：把外部文档变成可检索的知识库，再让大模型基于检索结果回答问题。

1. 核心概念（记住这5个）

概念 作用 生活类比
Document 原始文档（PDF、网页、txt） 一摞书
Node 文档被切分后的最小单元（一段文本） 书被拆成一个个段落卡片
Index 对 Node 建立索引（通常是向量索引），方便检索 图书馆的目录柜
Retriever 根据查询从 Index 中找回最相关的 Node 图书管理员
QueryEngine 整合 Retriever 和 LLM，完成“检索→生成”全流程 一个问答柜台：你问问题，管理员找书，然后读给你听

3. 进阶技术（简历中提到的）

节点解析器（Node Parser）

  • SentenceSplitter：按句子边界切分，可设置 chunk_size（每块最大字符数）和 overlap（重叠字符数，防止切断关键信息）。
  • SemanticChunker：按语义相似度切分，LLM 先判断哪里是语义边界，更智能但慢。

自定义检索器（混合检索）

重排序（Rerank）

  • 为什么需要：初检索可能召回 10 个节点，但只有 3 个相关。用重排序模型（如 BAAI/bge-reranker-base）重新打分，取最相关的 Top-K。

索引与存储上下文分离

  • Index：只负责逻辑结构（如向量索引的树形结构）
  • StorageContext：负责实际存储（向量存在 FAISS 里，文档存在磁盘上）
  • 好处：可以换后端存储而不改索引逻辑。

三、LangChain vs LlamaIndex — 什么时候用谁？

场景 推荐工具
简单 RAG（文档问答） LlamaIndex（更专注，API 更简洁）
需要多步推理、调用工具、Agent LangChain + LangGraph
复杂的文档处理（层次结构、表格） LlamaIndex（有专门的 TableRetriever）
纯 Chain（不涉及检索） LangChain
两者混合：用 LlamaIndex 管理索引，用 LangChain 做 Agent 完全可以！LlamaIndex 提供了 as_query_engine 可以直接作为 LangChain 的 Tool

四、记忆卡片（快速回顾）

LangChain & LangGraph

  • Chain：串联步骤
  • LCEL：| 管道符
  • Memory：存对话历史
  • Callback：监控日志
  • Tool：@tool 包装函数
  • LangGraph：状态图 + 循环 + 条件边，解决死循环/重规划

LlamaIndex

  • Document → Node → Index → Retriever → QueryEngine
  • 解析器：SentenceSplitter（按句子）、SemanticChunker（按语义）
  • 检索：向量 + BM25 混合
  • 重排序：用 Reranker 提升精度
  • 存储分离：Index 逻辑 vs StorageContext 物理

五、动手小实验（最快掌握）

  1. LangChain：用 LLMChain + ConversationBufferMemory 做一个简单的聊天机器人。
  2. LangGraph：照抄官网的“Basic ReAct Agent”示例，跑通并画出状态图。
  3. LlamaIndex：下载 10 页 PDF，用 VectorStoreIndex 搭建一个问答系统，然后加上 BM25 和 Rerank，对比效果。
